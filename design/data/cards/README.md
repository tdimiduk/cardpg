# Data Directory & Card Schema

This directory contains the source-of-truth definitions for all Cards, Items, and Encounters. These YAML files are processed by the build pipeline to generate the final assets for the VTT and printed cards.

## Notation Syntax

The build pipeline uses specific shorthand to render game icons and dynamic values. Use these codes in the `flavor`, `effects`, and `attack` fields.

### Dynamic Stack Values
These codes calculate the total value of the cards in the stack used to power the action.

* **`|x|`** -> **Red (Square)**: Sum of all Red values in the stack.
* **`|y|`** -> **Yellow (Circle)**: Sum of all Yellow values in the stack.
* **`|z|`** -> **Blue (Diamond)**: Sum of all Blue values in the stack.

*Example:* `power: "|z| + 4"` renders as "Attack [Blue Diamond] + 4", meaning "Sum of Blue values + 4".

## YAML Schema Reference

### Core Stats
* **`stats`**: The base values of the card itself.
    * `red`, `yellow`, `blue`: (Integer) The value printed in the top-left corner.

### Cost & Resources
* **`cost.resources`**: (Integer) The "Printed Cost" of the card.
    * **Rule:** This is the number of *additional* cards (resources) that must be added to the stack when playing this card.
    * *Example:* `resources: 1` means you play the Action Card + 1 Resource Card (Total Stack Size: 2).

### Action Definitions
* **`attack`**: Defines an offensive action.
    * `color`: The Pillar of the attack (Red, Yellow, Blue).
    * `power`: The formula for the attack's Strength (e.g., `|x|`, `|x| + 2`).
* **`stance`**: Defines a self-affecting, persistent martial or mental posture. (Mutually exclusive; entering a new Stance ends the previous one).
    * `duration`: Narrative or mechanical duration (e.g., "Encounter", "While conscious").
* **`prime`**: Defines a prepared reaction or trap waiting for a trigger.
    * `trigger`: The condition that activates the effect (e.g., "When anyone attacks you").
    * `reaction`: The specific action generated by the trigger.
* **`channel`**: Defines an ongoing magical or environmental effect that requires focus/maintenance.
    * `duration`: Narrative or mechanical duration (e.g., "Encounter", "4 turns").


### Metadata
* **`tags`**: List of keywords used for filtering and VTT automation (e.g., `[Fire, Magic, Ranged]`).

## Design Standards & Balance

### Action Costs
The game relies on a specific economy of card draws. Costs should adhere to these baselines to preserve the intended pacing.

* **Cost 1 (Fast):** Very quick actions. Allows a player to attack and defend/move in the same turn (given 2 draws/turn). Should have lower power scaling.
* **Cost 2 (Standard):** The baseline for a significant action (Sword swing, standard spell). A player generally cannot sustain Cost 2 actions every turn without eventually fatiguing or taking a turn to recover.
* **Cost 3+ (Heavy):** Major commitments (Haymakers, Rituals). These deplete the hand rapidly and signal a "finisher" or high-risk move.

### Defense Cards
Defense cards are `Type: Reaction` cards designed to be played from the hand during the Resolve Step.

* **The Mechanic:** Playing a card from hand adds its stats to the Defense Total but **does not increase Impact**. This is the primary way players mitigate Consequences—by spending resources (cards in hand) to reduce the number of cards they need to blind-flip from their deck.
* **Special Defenses:** Some cards may modify the calculation entirely (e.g., "Defend Red using Blue").
