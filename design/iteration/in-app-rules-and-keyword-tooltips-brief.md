# Brief: In-App Rules Viewer & Interactive Keyword Tooltips (Phase 5)

## Objective

Connect the Reflex-DOM rules rendering engine ([`Frontend.Render.Pandoc`](../../client/src/Frontend/Render/Pandoc.hs)) and canonical glossary model ([`Core.Glossary`](../../core/src/Core/Glossary.hs)) directly into the live client application:

1. **In-App Rules & Glossary Viewer:** An accessible slide-out drawer or modal in [`Frontend.App`](../../client/src/Frontend/App.hs) allowing players and GMs to reference Core Rules, the Keyword Glossary, and Colors of Action during gameplay.
2. **Unified Card Keyword Tooltips:** Upgrade card rich text rendering ([`Frontend.Render.Rules`](../../client/src/Frontend/Render/Rules.hs)) so inline `[[Keyword]]` links on cards render rich interactive hover/focus popovers identical to documentation badges.

---

## Architecture & Data Flow

```
client/static/{rules,glossary-ast,colors,glossary}.json (Generated by scripts/recompile-assets)
       │
       ▼  Compile-Time Embedding (TemplateHaskell / file-embed)
  Frontend.Rules.Data (embeddedGlossary :: Glossary, embeddedDocs :: Map DocId Pandoc)
       │
       ├──> In-App Rules Viewer Modal (Frontend.Rules.Viewer)
       │      │
       │      ▼  RenderEnv embeddedGlossary RenderInteractive
       │    renderPandoc env docAST
       │      └──> Interactive tabs: [Core Rules] [Glossary] [Colors of Action]
       │
       └──> Card Body & Rules Rendering (Frontend.Render.Rules)
              │
              ▼  lookupGlossary embeddedGlossary target
            renderInteractiveWikilink env target display mEntry
              └──> Instant hover/focus popovers on all card text
```

## Detailed Implementation Tasks

### Task 1: Compile-Time Rules & Glossary Embedding (`Frontend.Rules.Data`)

- Create `client/src/Frontend/Rules/Data.hs`.
- Embed the pre-generated JSON files at compile time:
  - `client/static/glossary.json` -> decoded into `Glossary`.
  - `client/static/rules.json`, `client/static/glossary-ast.json`, `client/static/colors.json` -> decoded into `Pandoc`.
- Decode eagerly into top-level pure values with fallback defaults.
- **Why compile-time embedding:** Eliminates runtime HTTP latency, avoids WebSocket messaging churn, and guarantees synchronous availability in static Reflex test harnesses (`client-test`).

### Task 2: In-App Rules Viewer Drawer/Modal (`Frontend.Rules.Viewer`)

- Create `client/src/Frontend/Rules/Viewer.hs`.
- Define active tab state:
  ```haskell
  data RulesTab = TabCoreRules | TabGlossary | TabColors
    deriving (Eq, Ord, Enum, Bounded, Show)
  ```
- Implement `rulesViewerWidget :: (DomBuilder t m, PostBuild t m) => Event t () -> m (Event t ())`:
  - Overlay modal / slide-out drawer styled with `obsidian-panel`, `bgStoneDark`, and `borderGoldMuted`.
  - Top navigation tab bar (Cinzel font, gold active indicators).
  - Scrollable content container (`overflowYAuto`, `maxW4Xl`, `mxAuto`, `p S6`).
  - Close button & ESC key dismissal returning close event.
  - Render document content using `renderPandoc (RenderEnv embeddedGlossary RenderInteractive) docAst`.

### Task 3: Trigger Integration in Client Navigation (`Frontend.Game.Sidebar` / `Frontend.App`)

- Add a "Rules & Reference" button / icon to the left sidebar header or footer in [`Frontend.Game.Sidebar`](../../client/src/Frontend/Game/Sidebar.hs).
- Wire the click event to open the `rulesViewerWidget` overlay in [`Frontend.App.uiWidget`](../../client/src/Frontend/App.hs).

### Task 4: Card Rich Text Keyword Tooltip Unification (`Frontend.Render.Rules`)

- Update [`Frontend.Render.Rules.renderInline`](../../client/src/Frontend/Render/Rules.hs):
  - For `Wikilink target mLabel`:
    - Look up `target` in `embeddedGlossary`.
    - Render the interactive popover widget (`game-kw-interactive`, `game-kw-badge`, tooltip card with Cinzel title, category badge, Lora summary, and SVG action color chips for `[[Red]]`, `[[Yellow]]`, `[[Blue]]`).
- Ensure card hover/focus tooltips share identical design tokens with rules documentation tooltips.

## Acceptance Criteria

1. **In-App Rules Viewer:**
   - Clicking "Rules" in the sidebar opens the rules drawer/modal.
   - Switching tabs seamlessly swaps between Core Rules, Glossary, and Colors of Action without network lag.
   - Wikilinks inside the viewer render working interactive popovers.
   - Modal closes cleanly via close button or click outside.
2. **Card Tooltips:**
   - Any card containing `[[Keyword]]` wikilinks displays a styled keyword badge chip.
   - Hovering or keyboard-focusing the badge displays the rich tooltip popover showing category, definition, and SVG action color chips.
3. **Quality & Verification:**
   - `cabal test all` passes 100% (including client unit tests for modal state and card wikilink DOM).
   - `./scripts/lint` passes with 0 hints and clean weeder.
   - `nix build .#reflex-client-prod` succeeds cleanly.
